# ADR-005: Caching Strategy

## Status
Accepted

## Context
Queue status and dashboards require low latency under bursty traffic.

## Decision
Use Redis for cache, rate limits, and short-lived distributed locks; PostgreSQL remains authoritative.

## Alternatives
Database-only caching, Memcached, client-only polling.

## Consequences
Hot reads and coordination improve, but cache invalidation and lock safety must be designed carefully.
